# peakora-web-template — сайт-заглушка для нод

Дата: 2026-08-26. Статус: дизайн согласован, реализации нет.

## 1. Задача

На каждой ноде Remnawave стоит nginx, который слушает `unix:/dev/shm/nginx.sock ssl proxy_protocol`;
Xray в режиме self-steal Reality отправляет туда весь трафик, не опознанный как VPN. Значит на домен
ноды (`pl.peakora.network`, `de.peakora.network`, …) приходят: активные пробы цензора, интернет-сканеры,
абуз-деск хостера и случайные люди, руками набравшие адрес. Сейчас им отдаётся `/var/www/html` без
содержимого.

Шаблон закрывает эту дыру: один статический сайт, одинаковый на всех нодах.

**Цели**

1. Правдоподобный законченный сайт, а не болванка.
2. Один артефакт на все локации; добавление ноды не требует правок шаблона.
3. Ни страница, ни её исходники не раскрывают состав парка нод.
4. Ни слова о VPN и о стеке, который стоит за ним.

**Не цели**

Работающий сервис, формы, бэкенд, аналитика, индексация в поиске, поддержка светлой темы,
локализация.

## 2. Легенда

**Peakora Network — оператор edge-инфраструктуры.** Легенда согласована с доменом `.network` и сама
собой объясняет схему поддоменов `<код-страны>.peakora.network`: у сетевого оператора точки присутствия
именно так и называются.

Жёсткие ограничения на текст:

- **Никаких проверяемо-ложных фактов.** Номер автономной системы, запись в PeeringDB, реквизиты
  юрлица, физические адреса, «uptime 99.99 % с 2019 года», числовые метрики трафика — запрещены.
  Их тривиально опровергнуть, а пользы ноль. Формулировки — общие и неопровергаемые.
- **Запрещённые слова** в собранном `dist`: vpn, proxy, xray, reality, remnawave, marzban,
  shadowsocks, vless, trojan. Проверяется тестом (§8).
- Ссылок на `peakora-cabinet`, бота и панель нет.

## 3. Определение локации

Страница показывает страну текущего узла, но **карту «поддомен → локация» не везёт**. Такая карта была
бы одинаковой на всех нодах, и одного запроса к любой ноде хватило бы, чтобы получить список всех
остальных.

Вместо этого — разворачивание кода страны средствами самого браузера, **через `Intl.DisplayNames`**:

1. Взять `location.hostname`, отрезать первую метку (`pl.peakora.network` → `pl`).
2. Если это ровно две латинские буквы — спросить
   `new Intl.DisplayNames(['en'], { type: 'region', fallback: 'none' }).of(cc)`.
3. Вернулось имя — показать страну; вернулось `undefined` — нейтральный вариант.

Таблицы кодов в бандле **нет вообще, ноль байт данных**: при `fallback: 'none'` неизвестный код даёт
`undefined`, и это же служит проверкой валидности. Проверено на Node 24 с полным ICU: `PL` → Poland,
`DE` → Germany, `UK` → United Kingdom (ICU сам ведёт алиас на GB), `XQ` и `AA` → `undefined`.
Исключаются вручную только псевдорегионы `ZZ` («Unknown Region»), `QO`, `XA`, `XB` — они резолвятся,
но странами не являются. Если `Intl.DisplayNames` в браузере нет, страна не показывается —
см. прогрессивное улучшение ниже.

Решение не только компактнее таблицы, но и не требует поддержки: новые коды приезжают с обновлением
браузера. О парке нод оно, как и таблица, не говорит ничего.

Флаг вычисляется из тех же двух букв через regional indicator symbols — ноль ассетов. На системах без
цветных emoji-флагов (Windows) он деградирует в две буквы, поэтому флаг декоративен: рядом всегда
текстовое название страны.

**Прогрессивное улучшение.** В HTML зашит нейтральный вариант («Edge node»); JS только уточняет его до
«Poland · Edge node». При выключенном JS страница остаётся осмысленной и целой.

В коде страницы нет ни одного хостнейма ноды, IP-адреса или списка локаций.

## 4. Содержание страницы

Одна страница, вертикальный поток, якорная навигация.

| Блок | Содержимое |
|---|---|
| Header | Знак Peakora + wordmark «Peakora Network»; якоря `Network`, `Infrastructure`, `Contact` |
| Hero | Заголовок, подзаголовок об edge-инфраструктуре |
| Node card | Страна (или нейтрально), роль `Edge node`, статус `Operational`, бейджи `IPv4 / IPv6`, `TLS 1.3`, `HTTP/2` |
| Infrastructure | Три карточки: `Edge delivery`, `Transit & routing`, `Operations`. Общие формулировки |
| Footer | `© <год> Peakora Network`, контакт `abuse@peakora.network`, якорь наверх |

Год проставляется при сборке и обновляется скриптом при загрузке — статический год протух бы, а без JS
осталась бы верная на момент сборки величина.

`abuse@peakora.network` — единственная константа в `src/config.js`. **Ящик обязан реально принимать
почту**: отбивающийся abuse-адрес хуже отсутствующего. У проекта есть `peakora-mail`, так что это
выполнимо.

Отдельная страница `404.html` — та же шапка и футер, короткий текст, ссылка на `/`.

## 5. Технические требования

- **Ноль внешних запросов** со страницы. Шрифты, стили, скрипты — только свои. Причина: заглушка
  открывается из страны с блокировками, внешний CDN может не ответить, и проба увидит поехавшую
  вёрстку вместо нормального сайта. Проверяется тестом (§8).
- **Ноль зависимостей** — и рантайм, и сборочных. Только стандартная библиотека Node 20+.
  Каталога `node_modules` в репозитории нет.
- Тема одна, тёмная. Токены берутся из `peakora-cabinet/frontend/src/styles/tokens.css`: фон `#070b16`,
  aurora-градиенты, glass-панели, радиусы `26/18/12 px`.
- Шрифты: **Space Grotesk 600** (заголовки) и **Inter 400/500** (текст), woff2, подмножество
  latin + latin-ext, self-hosted, `font-display: swap`. Оба под SIL OFL — самостоятельный хостинг
  разрешён, файл лицензии кладётся рядом (`src/assets/fonts/OFL.txt`).
- Ни cookie, ни localStorage, ни аналитики, ни внешних пикселей.
- `prefers-reduced-motion: reduce` гасит анимацию aurora.
- Респонсив 360–1920 px. Контраст по WCAG AA, семантические теги, видимый `:focus-visible`.
- **Ни одного инлайнового `<script>` и ни одного атрибута `style=`** — иначе страница ломается о CSP
  из §7. Это касается и знака Peakora, который инлайнится в разметку: его SVG использует
  презентационные атрибуты `fill=`, а не `style=` (в отличие от `favicon.svg` из кабинета).

**Бюджет размера** (проверяется тестом): `index.html` ≤ 30 KB, шрифты суммарно ≤ 100 KB,
весь `dist` ≤ 250 KB.

## 6. Сборка

`build.mjs`, запуск `node build.mjs`. Шаги:

1. Очистить `dist/`.
2. Минифицировать **только CSS**: снять комментарии и схлопнуть пробелы, не трогая `:` и `,`.
   JS копируется как есть, HTML — с удалением комментариев. Причина: `lib.js` и `app.js` вместе
   меньше двух килобайт, а самодельный JS-минификатор ломается об ASI, регулярные литералы и
   шаблонные строки. Бюджет из §5 выполняется и без этого с запасом.
3. Посчитать sha256 от содержимого, вставить восемь символов в имя: `assets/app.<hash>.js`,
   `assets/lib.<hash>.js`, `assets/styles.<hash>.css`, `assets/<font>.<hash>.woff2`.
4. Переписать спецификатор импорта в `app.js` на хэшированное имя `lib`. Бандлера нет:
   браузер грузит те же два ES-модуля, что импортирует Node в тестах. Порядок хэширования —
   от листа к корню: сначала `lib.js`, затем `app.js` с уже подставленным именем.
5. Подставить имена в `index.html` и `404.html`, инлайнить знак Peakora, проставить год.
   Скрипт подключается как `<script type="module" src="/assets/app.<hash>.js"></script>` —
   модули откладываются по умолчанию, `defer` не нужен.
6. Скопировать в корень `dist/`: `favicon.svg`, `favicon.png`, `apple-touch-icon.png`, `robots.txt`.
7. Напечатать размеры файлов и итог.

Хэши в именах ассетов и `no-cache` на HTML — это ровно то, чего требует политика кэширования из §7.

`favicon.png` (32×32) и `apple-touch-icon.png` (180×180) генерируются **один раз** отрисовкой
`favicon.svg` в headless-браузере и коммитятся в `src/assets/`. Сборка их не трогает — иначе
понадобился бы PNG-энкодер, а зависимостей нет.

**OG-теги.** В `<head>` идёт минимальный набор `og:type`, `og:site_name`, `og:title`, `og:description`,
`og:locale`. `og:image` и `og:url` не ставятся: они требуют абсолютного URL, который на каждой ноде
свой, а превью ссылок для домена ноды и не нужны. `<meta name="generator">` отсутствует —
это отпечаток.

## 7. nginx

`deploy/nginx/peakora-node.conf` — фрагмент, подключаемый **внутрь существующего `server {}`** ноды:

```nginx
server {
    server_name pl.peakora.network;
    listen unix:/dev/shm/nginx.sock ssl proxy_protocol;
    http2 on;
    ssl_certificate     "/etc/nginx/ssl/peakora/fullchain.pem";
    ssl_certificate_key "/etc/nginx/ssl/peakora/privkey.pem";

    include /etc/nginx/snippets/peakora-node.conf;
}
```

Блок ноды не переписывается: SNI, сертификаты и `listen` остаются как есть, заменяются только
`root`, `index` и `add_header` в конце.

Фрагмент задаёт:

- `root /var/www/html; index index.html; server_tokens off;`
- `location /assets/` — `expires 1y`, `Cache-Control: public, immutable` (имена с хэшем);
- `location /` — `try_files $uri $uri/ =404`, `Cache-Control: no-cache, must-revalidate`;
- `error_page 404 /404.html` и `location = /404.html { internal; }`. **Это главный выигрыш:** сейчас
  любой несуществующий путь отдаёт дефолтную страницу nginx с его версией — прямой маркер пустого
  хоста с болванкой;
- заголовки: существующий `X-Robots-Tag`, плюс `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`,
  `Content-Security-Policy: default-src 'self'; img-src 'self' data:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`.

Заголовки **дублируются в каждом `location`** намеренно: в nginx первый же `add_header` внутри
`location` отменяет все унаследованные с уровня `server`, и нынешний `X-Robots-Tag` молча пропал бы.
Вариант через `map $uri $cache_control` на уровне `http` убрал бы дублирование, но потребовал бы
второго фрагмента вне `server {}` — ради трёх строк не стоит.

`robots.txt` — `User-agent: * / Disallow: /`, согласованно с `X-Robots-Tag: noindex`.

## 8. Тесты

`node --test tests/`, без зависимостей.

| Тест | Что проверяет |
|---|---|
| `no-external-requests` | В `dist/**/*.{html,css,js,svg}` нет `http://`, `https://`, протокол-относительных `//` в `src`/`href`/`url()`/`@import`/`fetch(`. Белый список — только `xmlns="http://www.w3.org/2000/svg"`: это неймспейс, а не запрос. **Именно этот тест не даёт повторить ошибку кабинета с Google Fonts** |
| `no-forbidden-terms` | В `dist` нет слов из §2, регистронезависимо |
| `country-resolution` | Чистая функция: `pl.peakora.network` → Poland; `PL.…` → Poland; `philipp.…` → null; `peakora.network` → null; `xx.…` (нет в ISO) → null; `localhost` → null; пустая строка → null |
| `head-contract` | Есть `<title>`, `lang="en"`, `charset`, `viewport`, `description`, `robots=noindex`; нет `generator` |
| `size-budget` | Границы из §5 |

Конфиг nginx в тестах не поднимается — вместо этого `install.sh` вызывает `nginx -t` перед
перезагрузкой.

Визуальная проверка вручную: скриншоты headless-браузером на 390 px и 1440 px, `curl -I` на `/` и на
заведомо несуществующий путь.

## 9. Деплой

`dist/` коммитится в репозиторий — на ноде не нужен ни Node, ни сборка.

`deploy/install.sh` (bash, идемпотентен):

- `--root <путь>` (по умолчанию `/var/www/html`), `--no-snippet` — не трогать конфиг nginx;
- копирует `dist/` в root, выставляет `644` на файлы и `755` на каталоги;
- кладёт фрагмент в `/etc/nginx/snippets/peakora-node.conf`, сохранив предыдущую версию рядом;
- `nginx -t`; при успехе `systemctl reload nginx`, при ошибке — вернуть фрагмент из бэкапа и выйти
  с ненулевым кодом;
- строку `include` в конфиг ноды скрипт **не** добавляет: server-блоки у всех разные, автоправка
  чужого конфига опаснее одной ручной строки. README показывает, куда её вписать.

Обновление ноды: `git pull && sudo deploy/install.sh`.

## 10. Структура репозитория

```
src/
  index.html  404.html  styles.css
  lib.js                         чистая логика: страна, флаг, подписи, константы
  app.js                         привязка к DOM, импортирует lib.js
  assets/  logo.svg  favicon.svg  favicon.png  apple-touch-icon.png  robots.txt
           fonts/  *.woff2  OFL.txt
build.mjs
tools/   fetch-fonts.mjs          разовая выкачка woff2, в сборке не участвует
dist/                             собранный сайт, коммитится
deploy/  install.sh  nginx/peakora-node.conf
tests/   *.test.mjs
docs/superpowers/{specs,plans}/
.gitattributes  package.json  CLAUDE.md  README.md
```

`CLAUDE.md` — как в соседних репозиториях Peakora.

`.gitattributes` обязателен: репозиторий ведётся на Windows, а `install.sh` и фрагмент nginx едут на
Linux. С CRLF `install.sh` падает с `bad interpreter: /bin/bash^M`. Правило — `* text=auto eol=lf`,
плюс `-text` на `*.woff2` и `*.png`.

`package.json` — только `scripts` (`build`, `test`) и `"private": true`. Секции `dependencies` и
`devDependencies` отсутствуют, `node_modules` не появляется.

## 11. Зафиксированные решения

- Язык интерфейса — только английский, переключателя нет.
- Тема — только тёмная.
- Контакт — `abuse@peakora.network`, одна константа в `src/config.js`; ящик должен реально работать.
- Год в футере — из сборки, уточняется скриптом.
- Список локаций на странице не публикуется ни в каком виде.
