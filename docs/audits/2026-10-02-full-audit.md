### WEB-01 — reload игнорирует явно выбранный nginx

**Воспроизведение.** На машине есть активный host nginx, но установщик запускается с `--nginx "docker exec ... nginx"` или другим отдельным бинарником. `find_nginx()` сохраняет явную команду; `-t` проверяет именно её. `reload_nginx()` независимо выбирает `systemctl reload nginx`, если host unit активен. Нужный контейнер/процесс не получает reload, хотя установщик выводит `OK: nginx перезагружен`.

**Локальное доказательство.** В безопасной временной директории Git Bash запускал настоящий install.sh с `--nginx fixture-nginx`, подставным systemctl и отдельными root/snippet путями. Код завершения 0, журнал: `fixture-nginx -t`, `systemctl is-active --quiet nginx`, `systemctl reload nginx`; вызова `fixture-nginx -s reload` нет. Настоящие службы не затрагивались.

**Причина.** Выбор reload производится по наличию активного системного unit, а не по тому же выбранному исполнителю, который проверял конфигурацию.

**Минимальное исправление.** Связать проверку и reload с одним выбранным исполнителем; для явно переданного nginx применять его `-s reload`. Системный reload допустим только для выбранного системного nginx. Не добавлять общую абстракцию деплоя.

**Проверка исправления.** Исполняемый тест с подставными командами: явный executor при активном host unit, автоматически выбранный host nginx и найденный контейнер. Проверять фактические вызовы, а не только regexp исходника.

### WEB-02 — повторное копирование сохраняет временную надпись

**Воспроизведение.** Нажать COPY дважды с интервалом меньше 1600 мс, дождаться обоих таймеров. Второй обработчик сохраняет `original = 'Copied'`, затем его таймер возвращает Copied вместо COPY.

**Доказательство.** В Playwright clipboard заменён успешной локальной заглушкой до загрузки модуля. После двух кликов и ожидания 1,8 с итоговый текст кнопки — `COPIED`. Скриншот `ui-2026-10-02/repeat-copy.png`, результаты `ui-2026-10-02/results.json`.

**Причина.** Исходный текст берётся при каждом клике из уже изменённого DOM; независимые таймеры не отменяются.

**Минимальное исправление.** Сохранить постоянную исходную подпись при привязке обработчика и отменять предыдущий reset таймер или блокировать повторное подтверждение до сброса. Сохранить существующее поведение при отказе clipboard: не показывать ложное успешное копирование.

**Проверка исправления.** Тест с последовательностью двух успешных копирований и управляемыми таймерами; отдельно отказ clipboard.

### WEB-03 — защитные заголовки отсутствуют на 404

`deploy/nginx/peakora-node.conf:34–39` задаёт собственные add_header для 404 location. Они отменяют наследование заголовков, а CSP и Referrer-Policy в общем HTML location сюда не применяются. Это конкретное расхождение с инструкцией AGENTS о повторении security headers в каждом location и комментарием самого snippet; статический 404 не показал XSS. Минимальный hardening fix — повторить эти два согласованных заголовка для 404 HTML, сохранить internal и HTTP 404. Проверить snippet assertion и, когда доступен реальный nginx, response headers неизвестного пути. Локальный Python server такую наследуемость не моделирует.
