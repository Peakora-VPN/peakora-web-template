# AGENTS.md

Инструкции для Codex при работе с этим репозиторием.

## Обзор проекта

**peakora-web-template — статический сайт, который nginx отдаёт на домене узла
Peakora Network.** Один и тот же `dist/` раскатывается на все ноды; страна узла
определяется в браузере из `location.hostname`, никакой конфигурации на ноде для
этого не нужно.

Зависимостей нет вообще — ни рантайм, ни сборочных. `node_modules` в репозитории
не появляется. Node (≥ 20) нужен только для сборки и тестов; на ноде его нет.

```
src/layout.html   общий каркас: <head>, шапка, футер, плейсхолдеры
src/pages/*.html  содержимое страниц (index, network, 404)
src/site.json     контактный адрес — единственный источник
src/lib.js        чистая логика — импортируют и браузер, и тесты
src/app.js        привязка к DOM, импортирует lib.js
src/styles.css    тёмная тема, токены — подмножество peakora-cabinet
build.mjs         разворачивает каркас, хэширует ассеты, кладёт результат в dist/
deploy/           фрагмент nginx для include в server{} ноды и install.sh
tools/            разовые скрипты, в сборке не участвуют
```

## Команды

```bash
node build.mjs      # сборка в dist/
node --test         # все проверки
```

`node --test tests/` работать не будет: начиная с Node 22 позиционный аргумент
трактуется как модуль, а не как каталог, и падает с `MODULE_NOT_FOUND`. Нужен
именно голый `node --test` с авто-обнаружением.

## Как собираются страницы

Бандлера и генератора нет. `build.mjs` берёт `src/layout.html`, подставляет в
него содержимое каждого файла из `src/pages/` и разворачивает плейсхолдеры:
`{{TITLE}}`, `{{DESCRIPTION}}`, `{{CONTENT}}`, `{{YEAR}}`, `{{CONTACT}}`,
`<!--LOGO-->`.

Метаданные страницы лежат в её ведущем HTML-комментарии:

```html
<!--
title: Network — Peakora Network
description: ...
out: network/index.html
nav: network
-->
```

`out` задаёт путь внутри `dist`, `nav` помечает пункт меню атрибутом
`aria-current="page"`. Добавить страницу — значит положить один файл в
`src/pages/`; сборка подхватит его сама. Логотип инлайнится ДО удаления
комментариев, иначе плейсхолдер исчезнет вместе с ними.

Модули идут в браузер как есть: `app.js` импортирует `lib.js`, сборка лишь
переписывает спецификатор на хэшированное имя. Node в тестах импортирует те же
файлы — расхождению между тестом и продакшеном взяться неоткуда.

## Как страница узнаёт свою страну

Код страны из поддомена разворачивается через
`new Intl.DisplayNames(['en'], { type: 'region', fallback: 'none' })`. При
`fallback: 'none'` неизвестный код даёт `undefined`, и это же служит проверкой
валидности — таблицу ISO везти не нужно, в бандле ноль байт данных о странах.
Вручную отсекаются псевдорегионы `ZZ`, `QO`, `XA`, `XB`, `EU`, `EZ`, `UN`.

Распознаются `pl`, `pl2`, `pl-2`, `edge-pl-2`, `de-fra-01` и вложенные
метки вроде `edge.pl2`. Конфликтующие страны дают нейтральную подпись. Зона
домена не определяет страну; для распространённых составных зон учтены
`ac/co/com/edu/gov/net/org` перед двухбуквенной зоной. Это не полная Public
Suffix List — для нестандартных hosting-доменов границу нужно проверять.
Страна показывается в технических заметках и подвале, hostname не выводится.
Заголовки страницы и вкладки не меняются на название страны. Региональная
подпись — обозначение в имени, а не проверенная физическая геолокация.

Разметка содержит нейтральное «Edge node», скрипт лишь уточняет его. При
выключенном JS страница остаётся целой.

## Шкала рукопожатия

Сворачиваемый блок технических заметок главной — реальные измерения соединения из
Navigation Timing: DNS, TCP, TLS, TTFB и передача, нарисованные в масштабе
миллисекунд. Ничего не запрашивается и никуда не отправляется.

Нулевые фазы отбрасываются, а не рисуются пустыми: переиспользованное соединение
не проходит DNS и TCP заново, и показывать для них полоски — врать. Ширины
считает `phaseWidths` с полом в 8 %, иначе фаза в доли миллисекунды схлопнется в
невидимую полоску вместе с подписью. Ширина и порядковый номер приходят в CSS
кастомными свойствами через CSSOM (`element.style.setProperty`) — так можно:
CSP запрещает атрибут `style=` в разметке, но не запись через CSSOM.

## Интерактивные разделы

Главная посвящена инфраструктуре, а не текущему hostname. Схема запроса и
направления работы используют общий `wireTabs` из `src/app.js`. Панели полностью
лежат в HTML; до подключения JS кнопки скрыты, весь текст виден. Контроллер
назначает роли tablist/tab/tabpanel, управляет aria-selected и tabindex, поддерживает
стрелки и Home/End. Остальные раскрывающиеся блоки — нативные `<details>`.

Контакт в конце главной — рабочий `mailto:` на адрес из `src/site.json`
(плейсхолдер `{{CONTACT}}`), плюс копирование адреса через `wireCopyButtons`.
Письмо уходит почтовым клиентом посетителя: со страницы ничего не отправляется
и ничего не сохраняется. Кнопка копирования скрыта в разметке и появляется
только при живом буфере обмена — без JS контакт остаётся доступен как обычная
ссылка. Форм обращения на сайте нет и добавлять их не нужно.

## Оформление

Правило цвета, которого стоит держаться:

- `--accent` (бирюзовый `#37e0c9`) — **только живые измерения** этой сессии;
- `--accent-2` (сине-фиолетовый `#6a8bff`) — структура, знак, ссылки.

Разметка ведётся моноширинным начертанием (метки рельса, фазы, числа), проза —
Inter, заголовки — Space Grotesk. Aurora намеренно приглушена: она атмосфера, а
не главный элемент.

## Инварианты

Каждый существует по конкретной причине и стережётся тестом. Ломать нельзя;
если кажется, что нужно, — сначала перечитать
`docs/superpowers/specs/2026-08-26-node-decoy-site-design.md`.

- **Ноль внешних запросов со страницы.** Сайт открывается из стран с
  блокировками: внешний CDN может не ответить, и вместо нормальной страницы
  посетитель увидит поехавшую вёрстку. Шрифты лежат локально.
  Стережёт: `tests/dist.test.mjs`, «в dist нет ни одного внешнего запроса».
- **Ни инлайновых `<script>`, ни атрибутов `style=`.** Страница работает под
  `Content-Security-Policy: default-src 'self'` из фрагмента nginx; инлайн она
  просто не выполнит. Стережёт: `tests/markup.test.mjs`.
- **Список локаций не публикуется.** Карта «поддомен → город» была бы одинакова
  на всех нодах, и одного запроса к любой из них хватило бы, чтобы получить
  список остальных. Отсюда `Intl.DisplayNames` вместо таблицы.
- **Никаких проверяемо-ложных утверждений в текстах** — ни номера автономной
  системы, ни PeeringDB, ни юрлица, ни выдуманных метрик. Цифры на странице
  либо измерены браузером, либо их нет. Стережёт ревью; автоматически
  проверяется лишь отсутствие запрещённых слов (`vpn`, `xray`, `reality`,
  `remnawave` и прочих) в `dist`.
- **Ничего не запоминается и никуда не отчитывается**: ни cookie, ни
  localStorage, ни аналитики, ни единого `fetch`. Стережёт: `tests/dist.test.mjs`.
- **Заголовки дублируются в каждом `location` фрагмента nginx.** В nginx первый
  же `add_header` внутри `location` отменяет все унаследованные с уровня
  `server`. Стережёт: `tests/deploy.test.mjs`.

## Шрифты

Только подмножество `latin`. Проверено, что его `unicode-range` покрывает и все
строки страниц, и все английские названия регионов из ICU: диакритика
(`Curaçao`, `Åland Islands`, `Türkiye`) живёт в U+0000-00FF, типографский
апостроф из `Côte d’Ivoire` — в U+2000-206F. `latin-ext` стоил бы 182 KB ради
нуля видимых глифов. Inter отдаётся вариативным шрифтом: один файл на веса 400
и 500. Это зафиксировано тестом `tests/fonts.test.mjs` — если ICU когда-нибудь
вернёт символ вне диапазона, тест поймает это раньше глаза.

## Изменение текстов

Тексты английские, тема тёмная, переключателей нет — так решено в спеке.
Контактный адрес — поле `contact` в `src/site.json`; в разметке он стоит
плейсхолдером `{{CONTACT}}`. Ящик обязан реально принимать почту.
