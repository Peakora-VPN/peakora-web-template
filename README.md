# peakora-web-template

Статический сайт, который nginx отдаёт на домене узла Peakora Network. Один
артефакт на все локации: страна определяется в браузере из имени хоста, список
узлов нигде не публикуется.

`pl.peakora.network` покажет заголовком «Poland», `de.peakora.network` —
«Germany», неизвестный поддомен — нейтральное «Edge node». Правок шаблона при
добавлении ноды не требуется.

## Страницы

| Адрес | Что там |
|---|---|
| `/` | Кто это, шкала рукопожатия текущего соединения, три блока о сети, контакт |
| `/network/` | Путь запроса в четырёх шагах, операционная часть, вопросы и ответы |
| `404` | Отдаётся на любой другой путь вместо дефолтной страницы nginx |

Шкала рукопожатия — реальные измерения из Navigation Timing: DNS, TCP, TLS,
TTFB и передача, нарисованные в масштабе миллисекунд, плюс протокол соединения.
Считает всё браузер, наружу не уходит ничего. На переиспользованном соединении
часть фаз пропадает — это правда, а не сбой.

## Сборка

```bash
node build.mjs      # собирает dist/
node --test         # прогоняет проверки
```

Зависимостей нет — ни рантайм, ни сборочных. Нужен только Node 20 или новее,
и только на машине разработчика: на ноде лежит уже собранный `dist/`.

## Установка на ноду

```bash
git clone <repo> /opt/peakora-web-template
cd /opt/peakora-web-template
sudo deploy/install.sh
```

Установщик кладёт `dist/` в `/var/www/html`, ставит фрагмент в
`/etc/nginx/snippets/peakora-node.conf`, проверяет конфигурацию через `nginx -t`
и перезагружает nginx. Если проверка не прошла, фрагмент откатывается, а скрипт
завершается с ненулевым кодом. Если nginx вообще не найден, фрагмент остаётся на
месте: пока на него нет `include`, он ни на что не влияет.

Флаги: `--root DIR`, `--snippet-dst PATH`, `--no-snippet`, `--nginx CMD`.

### Если nginx в контейнере

Установщик сам находит контейнер с nginx и зовёт его через `docker exec`. Но у
контейнера своя файловая система: фрагмент, положенный на хост, внутри не
существует, и `include` уронит конфигурацию. Скрипт спрашивает об этом сам
контейнер и предупреждает.

Для стека Remnawave (`remnawave-nginx`, конфиг смонтирован файлом) порядок такой:

1. `bash deploy/install.sh` — статика и фрагмент оказываются на хосте.
   **Файл должен появиться до следующего шага:** если примонтировать
   несуществующий путь, Docker создаст на его месте каталог.
2. Пробросить фрагмент в контейнер — одна строка в `volumes` сервиса
   `remnawave-nginx` рядом с `./nginx.conf`:

   ```yaml
   - /etc/nginx/snippets/peakora-node.conf:/etc/nginx/snippets/peakora-node.conf:ro
   ```

3. `docker compose up -d` — контейнер пересоздаётся с новым томом.
4. Вписать `include` в блок `server` своего `nginx.conf` (см. ниже).
5. `bash deploy/install.sh` ещё раз — теперь он проверит конфигурацию и
   перезагрузит nginx.

Дальнейшие обновления — `git pull && bash deploy/install.sh`, конфиги трогать
уже не нужно.

Альтернатива без тома: вписать содержимое `deploy/nginx/peakora-node.conf`
прямо в блок `server` своего `nginx.conf`. Проще на один шаг, но при изменении
директив их придётся переносить руками на каждой ноде.

Одну строку в конфигурацию ноды нужно вписать руками — блоки `server` на разных
нодах различаются, и автоматическая правка чужого конфига опаснее ручной:

```nginx
server {
    server_name pl.peakora.network;
    listen unix:/dev/shm/nginx.sock ssl proxy_protocol;
    http2 on;

    ssl_certificate     "/etc/nginx/ssl/peakora/fullchain.pem";
    ssl_certificate_key "/etc/nginx/ssl/peakora/privkey.pem";

    include /etc/nginx/snippets/peakora-node.conf;
}
```

Строки `root`, `index` и `add_header` из блока при этом убираются: их задаёт
фрагмент. Он же добавляет то, чего в блоке не было: свою страницу 404 вместо
дефолтной страницы nginx с номером версии, кэширование ассетов и заголовки
безопасности.

Обновление: `git pull && sudo deploy/install.sh`.

## Что нужно проверить перед запуском

Ящик из `src/site.json` должен реально принимать почту: отбивающийся
abuse-адрес выглядит хуже, чем его отсутствие. Адрес правится **в одном месте** —
в разметке он стоит плейсхолдером `{{CONTACT}}`, который подставляет сборка.

## Как устроен репозиторий

```
src/layout.html   общий каркас страницы: <head>, шапка, футер
src/pages/*.html  содержимое страниц; ведущий комментарий задаёт title,
                  description, out (путь в dist) и nav (активный пункт меню)
src/site.json     контактный адрес
src/lib.js        чистая логика: страна, фазы соединения, форматирование
src/app.js        привязка к DOM
src/styles.css    тёмная тема, токены — подмножество peakora-cabinet
build.mjs         разворачивает каркас, хэширует ассеты, складывает dist/
deploy/           фрагмент nginx и install.sh
tools/            разовые скрипты, в сборке не участвуют
```

Новая страница — это один файл в `src/pages/` с блоком метаданных; сборка
подхватит его сама.

## Обновление шрифтов

```bash
node tools/fetch-fonts.mjs > faces.tmp.css
```

Скрипт перекачивает подмножества Inter, Space Grotesk и JetBrains Mono с Google
Fonts в `src/assets/fonts/` и печатает готовый блок `@font-face`, который
заменяет собой такой же блок в начале `src/styles.css`. В сборке он не
участвует и запускается вручную.

## Правила, которые ломать нельзя

- **Никаких внешних запросов со страницы.** Сайт открывается из стран с
  блокировками: внешний CDN может не ответить, и вместо нормальной страницы
  посетитель увидит поехавшую вёрстку.
- **Никаких инлайновых `<script>` и атрибутов `style=`**: страница работает под
  `Content-Security-Policy: default-src 'self'`.
- **Никаких проверяемо-ложных утверждений в текстах** — ни номера автономной
  системы, ни PeeringDB, ни юрлица, ни выдуманных метрик. Цифры на странице
  либо измерены браузером, либо их нет.
- **Список локаций не публикуется ни в каком виде.**

Всё перечисленное, кроме пункта про тексты, проверяется тестами в `tests/`.
Обоснования — в [`CLAUDE.md`](./CLAUDE.md) и в спеке `docs/superpowers/specs/`.
