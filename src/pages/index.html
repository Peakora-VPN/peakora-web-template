01 / Request path

From a name to a delivered page

The connection is a sequence, not a single event.

Each stage answers a different question. Select a stage to focus on it, or read the complete path without JavaScript.

01 / Resolve

Start with a name

Name resolution connects a domain to an address. A cached answer can let the browser move straight to the next stage without another lookup.

02 / Connect

Establish the connection

The browser negotiates a transport and, for a secure connection, completes a handshake. An existing connection may be reused instead.

03 / Request

Send the request

The request crosses the network and the server prepares a response. The wait for its first byte includes both parts of that journey.

04 / Deliver

Bring the response back

The response arrives in the browser, ready to be interpreted. The page can then request its styles, fonts and other resources.

02 / Infrastructure

The working layers

Different responsibilities. One delivery system.

The edge handles the client-facing boundary. Routing determines the path between endpoints. Operations keeps changes and observations understandable over time.

Edge delivery

Where a request meets the network.

The edge is a boundary between a client and the systems serving it. Name resolution, transport negotiation and response delivery all contribute to the experience on the other side.

Connection setup
Account for the cost of establishing a new connection and the benefit of reusing one.
Protocol negotiation
Let the client and server agree on a supported way to exchange requests and responses.
Response delivery

Transit & routing

The path matters as much as the destination.

A connection depends on the networks between its endpoints. Physical distance is only part of the picture: routing decisions, congestion and transport behavior also affect delivery.

Path awareness
Consider the complete route rather than treating the destination as the only variable.
Changing conditions
Expect a route's behavior to vary with the network, the client and the time of the request.
End-to-end context

Operations

Infrastructure is an ongoing practice.

Deployment is one moment in a system's life. Useful operations also depend on deliberate changes, clear observations and reports that carry enough context to act on.

Repeatable changes
Keep a clear baseline and make the effect of each change possible to review.

05 / Common questions

Context before conclusions.

What does edge infrastructure mean?

The edge is the client-facing boundary of a network or service. It is where connections are handled before requests move through the rest of a system. Delivery, transport and operational decisions meet at that boundary.

Why can two visits feel different?

The browser may reuse a connection or a cached name lookup. Network conditions can change too. The result is a different balance of setup, waiting and transfer time, even when the requested page is the same.

Why are some timing phases absent?

A cached lookup or reused connection can remove setup work from a navigation. Browsers can also restrict or round timing data. The readout omits phases reported as zero rather than inventing a duration.

Does one fast reading prove availability?

No. One navigation is a sample from one browser at one moment. Understanding a broader pattern requires repeated observations, timestamps and context about affected clients.

How do I report a network issue?

Use the contact address below. Include the affected address, timestamps in UTC, what you observed and whether the issue repeats or affects more than one network.
