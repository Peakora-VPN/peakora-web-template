Inside the request path.

A connection is a sequence of decisions and exchanges. Understanding its stages makes measurements more useful and network behavior easier to explain.

Request path

  1. 01 / Resolve

    A hostname becomes an address

    Your browser resolves this host's name before it can connect. If the answer is already cached, there may be no DNS phase to show.

  2. 02 / Connect

    The browser establishes a connection

    Connection and secure handshake timings appear when the browser reports them. A reused connection skips this work; newer transports may expose different timing boundaries.

  3. 03 / Request

    The browser waits for the first byte

    The TTFB phase measures the interval from sending the request to receiving the start of the response. It includes network travel and the time taken to prepare the response.

  4. 04 / Delivery

    The response reaches your browser

    The transfer phase ends when the page response has arrived. It does not include every image, font or stylesheet, and it is not a bandwidth test.

Protocol foundations

Separate responsibilities, shared purpose.

Different protocols solve different parts of delivery. Keeping those responsibilities distinct helps explain what a browser can observe.

Name resolution

DNS connects names to addresses. Its answer may be cached by the browser, the operating system or a resolver, so a lookup is not always visible in one page load.

Secure transport

A secure handshake establishes how a connection will protect data in transit. The transport and protocol in use affect which timing boundaries the browser reports.

HTTP delivery

HTTP describes the exchange of requests and responses. The negotiated version belongs to this connection; it is not a statement about every client or network path.

Reading the signals

A measurement needs its context.

Fresh and reused connections

A fresh connection may include resolution and a handshake. A reused one can move directly to the request. Missing setup phases can therefore reflect useful reuse rather than missing work.

One response and a complete page

The main document is only one resource. Styles, fonts and images can arrive separately. A document transfer duration does not describe the time needed to render every part of a page.

Waiting and transferring

Time to first byte includes the request's travel and response preparation. Transfer time begins when the response starts arriving. A change in one can happen without a similar change in the other.

A sample and a pattern

One observation is a starting point. Repeated behavior, timestamps and the scope of affected clients are needed to understand a broader issue. A fast sample is not an uptime record.

Questions

Why are some connection phases absent?

A cached lookup or a reused connection can remove setup work from a navigation. Browsers can also restrict or round timing data. The readout omits phases reported as zero rather than inventing a duration for them.

Why is the negotiated protocol sometimes unavailable?

A browser does not always expose the protocol identifier for a navigation. When the value is absent, the page leaves it unspecified rather than inferring it from the address or a connection duration.

Is the transfer duration a speed test?

No. A small page response is a different workload from a sustained transfer, and it can be affected by caching and timing precision. The reading describes this response, not the capacity of your connection.

The timings look different each time I load the page.

These readings describe one page load. Caching, connection reuse and the network path can change between visits. A zero or unreported phase is omitted, and very small segments are widened so their labels remain readable.
