01 / Resolve

A hostname becomes an address.

DNS connects a memorable name to a usable address. Browser, operating system and resolver caches can answer before a new network lookup is needed.

The lookup is conditional

A browser checks available caches before asking the configured resolver. A complete hierarchy walk is necessary only when no usable cached answer remains.

The measurement follows the work

A missing DNS phase can therefore mean a useful cached answer, not missing information about the page. Navigation Timing reports an interval only when the work occurred and the browser exposed it.

02 / Connect

The endpoints establish a transport.

A fresh connection must open before application data can move. A reused connection continues an existing channel and skips that setup.

Fresh setup
Opening a transport requires exchanges between client and server. Latency affects each exchange before a request can be sent.
Reuse
Persistent and multiplexed connections let later requests use an existing channel rather than repeat the opening work.
Observable boundaries
Navigation Timing can expose connection marks, but the visible phases depend on the transport and on whether setup actually happened.

Read the connection reuse note

03 / Secure

The channel negotiates protection.

For a secure connection, the endpoints authenticate and agree on encryption parameters before relying on the channel.

Authentication

The server presents a certificate binding its name to a public key. The client checks that chain of trust before using the channel.

Key agreement

The endpoints derive shared secrets for protecting data in transit without sending those secrets across the network.

Separate responsibilities

The secure handshake belongs to the connection. HTTP describes the requests and responses carried inside it; the two layers should not be conflated.

04 / Request

Waiting for the first byte has more than one cause.

Time to first byte begins with the request and ends when the response starts arriving. Network travel and response preparation both belong to this interval.

  1. 01 / Outbound

    The request crosses the path

    The request must reach the server before a response can be prepared. Its journey is already part of the waiting interval.

  2. 02 / Prepare

    The response is assembled

    Queueing and response generation also occur before the first byte can leave. The timing alone does not divide these causes.

  3. 03 / First byte

    The wait ends when arrival begins

    TTFB identifies how long the wait was; by itself it cannot identify which component made the wait long.

05 / Deliver

The response arrives. The page may still be assembling.

Transfer time runs from the first response byte to the last for this document. Styles, fonts and other resources are separate exchanges.

One document

The transfer interval describes this response's bytes. It does not include every resource needed to render the complete page.

Not a capacity test

A small document is a different workload from a sustained transfer. Its duration is not a measure of available bandwidth.

06 / Reading the signals

A measurement needs its context.

A useful reading starts with what the browser actually observed and stops short of claims the observation cannot support.

Fresh and reused connections

A fresh connection may include resolution and a handshake. A reused one can move directly to the request. Missing setup phases can therefore reflect useful reuse rather than missing work.

One response and a complete page

The main document is only one resource. Styles, fonts and images can arrive separately. A document transfer duration does not describe the time needed to render every part of a page.

Waiting and transferring

Time to first byte includes the request's travel and response preparation. Transfer time begins when the response starts arriving. A change in one can happen without a similar change in the other.

A sample and a pattern

One observation is a starting point. Repeated behavior, timestamps and the scope of affected clients are needed to understand a broader issue. A fast sample is not an uptime record.

Questions

When the reading needs an explanation.

Why are some connection phases absent?

A cached lookup or a reused connection can remove setup work from a navigation. Browsers can also restrict or round timing data. The readout omits phases reported as zero rather than inventing a duration for them. How reuse removes setup phases

Why is the negotiated protocol sometimes unavailable?

A browser does not always expose the protocol identifier for a navigation. When the value is absent, the page leaves it unspecified rather than inferring it from the address or a connection duration.

Is the transfer duration a speed test?

No. A small page response is a different workload from a sustained transfer, and it can be affected by caching and timing precision. The reading describes this response, not the capacity of your connection.

The timings look different each time I load the page.

These readings describe one page load. Caching, connection reuse and the network path can change between visits. A zero or unreported phase is omitted, and very small segments are widened so their labels remain readable. How to read a single sample
