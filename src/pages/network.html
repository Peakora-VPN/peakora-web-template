How a request moves

Four stages, in the order they happen. This host performs the first two of them for you right now.

Request path

  1. 01 / Ingress

    The connection lands at the nearest location

    Client resolvers are answered with the location closest to them, so the first packet travels the short way rather than across an ocean.

  2. 02 / Termination

    TLS ends here, not further in

    The handshake completes at the edge host. That is the number you saw on the front page: it is short because the host answering it is near you.

  3. 03 / Routing

    Onward paths are chosen, and re-chosen

    Each location carries more than one upstream. When a path degrades, traffic moves to another one instead of waiting for it to recover.

  4. 04 / Delivery

    The response comes back the same short way

    The return path reuses the connection already established, so subsequent requests skip the lookup and the handshake entirely.

Operations

One baseline, many locations

Every location is built from the same configuration and serves the same content. A location differs from its neighbours only in where it sits, which is why this page can name its country without knowing anything else about it.

Identical by construction

Hosts are provisioned from one baseline. Nothing is configured by hand on an individual location.

Watched continuously

Reachability and capacity are checked from outside the location, not only from within it.

Questions

Why does this hostname start with two letters?

The prefix is an ISO 3166-1 country code naming the location. Your browser turns it into a country name locally, using its own region data. The page carries no list of locations, so nothing about the rest of the footprint is published here.

Why is there nothing to log into?

This host serves static content and nothing else. Operational tooling is not exposed on it, which is why every other path returns a plain 404.

The timings look different each time I load the page.

They are your measurements, not ours. A reused connection skips the lookup and the handshake, so those stages disappear from the readout entirely on a second load.

How do I report abuse?

Write to {{CONTACT}} with timestamps in UTC and the address you observed. That is enough to locate the traffic.
